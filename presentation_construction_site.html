Le principe

Chaque entrée du menu pointe vers un .qmd : ajouter un indicateur = créer la page + ajouter 3 lignes dans le YAML

resources : déclarer ce que le JavaScript va chercher

  • Quarto copie dans _site/ ce qu’il voit dans les pages
  • Les fichiers chargés par fetch() ou par MapLibre ne sont pas détectés
  • Il faut donc les lister : au niveau du projet, ou dans l’en-tête de chaque page
resources:
  - layers/data_s31h_logt_inond_zx_q100.json
  - layers/valeurs_s31h.json
  - layers/batiments_perim_papi.pmtiles.gz
  - tableaux/*.html

Oubli classique : tout marche en local, puis le fichier manque une fois le site publié.

Quatre types de blocs dans une même page

Bloc Exécuté Où Sert à
{r} au rendu machine de build Produire des fichiers (tableaux)
{ojs} à l’ouverture navigateur Données et carte, avec dépendances entre cellules
{=html} jamais recopié tel quel Scripts, variables globales, CSS
::: {.callout-...} au rendu Markdown vers HTML Fiches d’information

Idée clé : le rendu Quarto prépare la page, le navigateur fait vivre la carte. Les deux mondes se parlent par des fichiers (layers/, tableaux/) et par des variables globales (window.*).

Chunk OJS n°1 : préparer les données

```{ojs}
//| echo: false
//| output: false
indicateursGeojson = {
  const gj = await FileAttachment("layers/indicateurs_debce.geojson").json();
  const r = await fetch("layers/valeurs_s31h.json");
  const vals = await r.json();
  gj.features.forEach(f => Object.assign(f.properties, vals[f.properties.insee_com]));
  gj.features.forEach((f, i) => { f.id = i + 1; });
  return gj;
}
```

Extrait simplifié. Les valeurs de l’indicateur sont rattachées à chaque commune par son code INSEE.

Faire communiquer les blocs : les variables window.*

// Bloc {=html}, exécuté tôt : valeurs par défaut et "boîte aux lettres"
window.TABLEAU_URL = "tableaux/debordement_s31h.html";
window.basculerAleaCarte = function (m) { window._modeAleaEnAttente = m; };

// Bloc {ojs} de la carte, quand tout est prêt : la vraie fonction
window.basculerAleaCarte = async function (nouveauMode) {
  cfgCourante = CONFIG_MODES[nouveauMode];
  window.TABLEAU_URL = cfgCourante.tableauUrl;
  window.GRAPHIQUE   = cfgCourante.graphique;
  /* recolorer la carte, recharger graphique et tableau */
};

Les blocs HTML s’exécutent tout de suite, les cellules OJS plus tard. Tant que la carte n’est pas prête, la demande de bascule est mise en attente dans _modeAleaEnAttente.

function corps(selecteur) {
  const el = document.querySelector(selecteur);      // ex. ".callout.ind-calcul"

La préparation des données, en amont

indicateurs <- st_read("layers/indicateurs_debce.geojson", quiet = TRUE) %>%
  st_drop_geometry() %>% select(nom, s31h_logt_inond_zx_q100) %>%
  mutate(s31h_logt_inond_zx_q100 = replace_na(s31h_logt_inond_zx_q100, 0))
write_json(indicateurs, "layers/data_s31h_logt_inond_zx_q100.json",
           auto_unbox = TRUE, na = "null")

Dans la page, ce bloc est commenté : il se lance à la main quand les données changent.

Ce qui se passe à quarto render

1. Configuration

Lecture de _quarto.yml : menus, thème, resources

2. Chaque page

{r} exécuté par R, {ojs} converti en JavaScript, callouts convertis en HTML

3. Copie

Fichiers de resources, js/, layers/, tableaux/ copiés dans _site/

4. Publication

Le dossier _site/ est servi par GitHub Pages

Pièges rencontrés

  • Chemins relatifs : ../layers/... dans les sous-dossiers, d’où SITE_BASE
  • Fichiers non copiés : tout ce qui est chargé par JavaScript doit figurer dans resources
  • Ordre d’exécution : blocs HTML immédiats, cellules OJS asynchrones, d’où la « boîte aux lettres » _modeAleaEnAttente
  • document.write : simple pour charger les scripts, mais bloquant et déconseillé
  • Pages très longues : environ 3 450 lignes, dont 2 200 pour la seule carte

Pistes d’amélioration

Sortir le JavaScript

Déplacer le code de la carte dans js/carte.js, partagé par toutes les pages

Factoriser avec include

{{< include _fiches.qmd >}} pour les callouts communs à toutes les pages

Paramétrer par page

Une petite configuration par indicateur (champ, seuils, fichiers) et un code commun
